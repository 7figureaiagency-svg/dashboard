# Plan 40.1: Micro-LLM Perception Layer, 3-Tier Multi-Tenant Scaling Pool & Structured Schema Router

<objective>
Build a high-speed, hyper-focused Micro-LLM Perception Layer (`intent_classifier.ts` / `cognitive_turn_router.ts`) that extracts real estate intent, entities, vernacular language, and role with 100% structured JSON precision (< 250ms, ~400 tokens per message), backed by a 3-tier multi-tenant scaling pool (Gemini 2.0 Flash primary -> Groq Llama 3.3 70B hot fallback -> Deterministic slot engine).
</objective>

<context>
- In Phase 39, we eliminated regexes, but the router still suffered from boundary issues when dual-role intents arose (e.g. "Mare maro juno flat bechvo che" misclassified as "SEARCH_PROPERTY").
- During our Phase 40 architecture review, we decided:
  1. AI's role must be strictly limited to **Perception & Understanding** (Intent, Entities, Dialect, Role). AI will NEVER make database decisions or write procedural hallucinated text.
  2. The prompt must be hyper-focused (~350-400 input tokens, ~60 output tokens = ~₹0.004 per message).
  3. High-load resilience: 3-tier scaling with Gemini 2.0 Flash (2,000 RPM) + Groq Llama-3.3-70b (instant hot fallback) + pure deterministic fallback.
</context>

         ```ts
         export interface MicroIntentResult {
           primary_intent:
             | "SEARCH_PROPERTY"      // User looking to buy/rent/lease
             | "SUBMIT_PROPERTY"      // User looking to sell/rent out/list
             | "DUAL_ROLE_INTENT"     // User mentions both: sell old + buy new
             | "SELECT_OPTION"        // User replies with digit/choice
             | "BOOK_VISIT"           // User confirms a site visit
             | "RESCHEDULE_VISIT"     // User requests date/time change
             | "CANCEL_VISIT"         // User cancels visit
             | "VISIT_ATTENDED"       // User confirms post-visit attendance
             | "VISIT_NOT_ATTENDED"   // User confirms post-visit absence
             | "ASK_FAQ"              // Side-question (RERA, Loan, Brokerage, Map)
             | "REQUEST_CALL"         // "Call me", "Kal 5 baje call karo", "talk to human"
             | "GREETING"             // "Hi", "Hello", "Kem cho", "Namaste"
             | "OPT_OUT"              // "Stop", "Don't message", "DND"
             | "OFF_TOPIC";           // Unrelated chitchat
           active_role: "BUYER" | "SELLER" | "DUAL_ROLE" | "UNKNOWN";
           detected_language: "GUJLISH" | "HINGLISH" | "ENGLISH" | "GUJARATI_SCRIPT";
           selected_option: number | null;
           entities: {
             property_type: string | null;      // "Flat", "Villa", "Commercial Shop", "Office", "Plot"
             unit_bhk: number | null;           // 1, 2, 3, 4, 5
             location: string | null;           // Clean English locality e.g. "Alkapuri", "Gotri"
             budget_inr: number | null;         // Pure integer in INR e.g. 10000000 (1 Cr), 8500000 (85L)
             possession_timeline: "READY_TO_MOVE" | "UNDER_CONSTRUCTION" | null;
             size_area_sqft: number | null;     // Carpet or plot sqft
             project_or_society: string | null; // Society name for sellers
             expected_price_inr: number | null; // Price for sellers
             transaction_type: "BUY" | "RENT" | "LEASE" | "SELL" | "RENT_OUT" | "LEASE_OUT" | null;
             visit_date_time: string | null;    // Raw visit string e.g. "Tomorrow 5 PM"
           };
           side_question: string | null;        // Exact FAQ question if user asked one alongside criteria
           user_negated_assumptions: boolean;   // True if "lena nahi, bechna hai"
           reasoning?: string;
         }
         ```
       - Ensure `routeCognitiveTurn` prompt explicitly defines every intent with concrete Hinglish & Gujlish examples.
       - Ensure vernacular selling vocabulary (`bechvo`, `bechvu`, `bechva`, `vechvo`, `vechvu`, `vechva`) is explicitly classified as `SUBMIT_PROPERTY` (or `DUAL_ROLE_INTENT` if combined with buying).
