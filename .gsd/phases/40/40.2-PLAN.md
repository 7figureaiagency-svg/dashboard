# Plan 40.2: Dual-Role Black-Board Slot Memory & Conversational Steering Engine

<objective>
Implement the Black-Board Slot Memory engine that isolates Buyer and Seller profiles inside `lead.metadata`, enforces the Fast-Track 4-Slot Buyer Qualification and 3-Slot Seller Intake, handles Dual-Role upgrade/relocation priority, and deploys the Anti-Derailment Conversational Steering Engine (AAS formula) to ensure the bot always holds the steering wheel.
</objective>

<context>
- Currently, buyer and seller data share the same fields in `leads` (`budget`, `location`, `property_type`), causing the severe context contamination observed in production (e.g. seller flat being matched against buyer ₹1 Cr Alkapuri budget).
- In our Phase 40 architecture review, we decided:
  1. **Dual Profiles**: `metadata.seeker_profile` (Buyer) and `metadata.seller_profile` (Seller) must be strictly isolated.
  2. **Buyer Fast-Track (4 Slots)**: (1) Type, (2) Location, (3) Budget, (4) Possession Timeline. Purpose defaults to 'Self-Use'.
  3. **Seller Fast-Track (3 Slots)**: (1) Type & Society/Project, (2) Size/Area, (3) Expected Price/Rent.
  4. **Dual-Role Priority**: When both are mentioned, ask user: *"Pehle naya flat explore karna chahenge ya purana flat list karna chahenge?"*, then bridge to the other.
  5. **Anti-Derailment (AAS Formula)**: Acknowledge (1 line) -> Answer Side-FAQ (1 line) -> Steer Back (repeat pending slot question). Bot always ends with 1 question.
</context>

         ```ts
         interface LeadSlotMemory {
           active_persona: "BUYER" | "SELLER";
           seeker_profile: {
             property_type: string | null;
             unit_bhk: number | null;
             location: string | null;
             budget_inr: number | null;
             possession_timeline: "READY_TO_MOVE" | "UNDER_CONSTRUCTION" | null;
             purpose: "SELF_USE" | "INVESTMENT";
             slots_filled: string[];
             is_fully_qualified: boolean;
             booked_visit?: { project: string; slot: string; scheduled_at: string };
           };
           seller_profile: {
             property_type: string | null;
             project_or_society: string | null;
             size_area: string | null;
             expected_price_inr: number | null;
             transaction_type: "SELL" | "RENT_OUT" | "LEASE_OUT";
             slots_filled: string[];
             is_submitted: boolean;
           };
           last_bot_prompt: {
             target_persona: "BUYER" | "SELLER" | "TRIAGE";
             question_type: "PROPERTY_TYPE" | "LOCATION" | "BUDGET" | "TIMELINE" | "SELLER_SOCIETY" | "SELLER_AREA" | "SELLER_PRICE" | "DUAL_PRIORITY" | "VISIT_SLOT" | "VISIT_ATTENDANCE";
             sent_at: string;
           };
         }
         ```
       - When user expresses seller intent (*"Mare maro juno flat bechvo che"*):
         - Set `lead_type = "DUAL_ROLE"`, `active_persona = "SELLER"`.
         - NEVER touch or evaluate `seeker_profile.budget` or `seeker_profile.location`.
         - Query missing slots strictly against `seller_profile`:
           1. Missing `project_or_society`? Ask society name.
           2. Missing `size_area`? Ask size/carpet sqft.
           3. Missing `expected_price_inr`? Ask price.
       - When all 3 seller slots are filled:
         - Insert into `property_submissions` table under `PENDING_VERIFICATION`.
         - Trigger Bridge Handoff back to buyer search if they also wanted to buy!
