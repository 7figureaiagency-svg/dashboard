# Plan 8.2: Strict Authentication Enforcement (Remove Demo/Direct Access) & Dynamic Multi-Tenant Dashboard

## Objective
Enforce strict credential authentication across the application by removing the "Direct Access Dashboard" demo mode bypass from `auth.tsx`, `_authenticated/route.tsx`, and `auth.ts`. Ensure dynamic multi-tenant branding and strict data isolation so that signing in as `kashyap@gmail.com` renders Griham Realty branding and data, while signing in as `admin@nextgenrealty.com` renders Nextgen Realty data.

Load these files for context:
- `.gsd/SPEC.md` (System vision, strict 100% Non-n8n rule, multi-tenant safety)
- `.gsd/ROADMAP.md` (Phase 8 Objectives)
- `.gsd/phases/8/8.1-PLAN.md` (Multi-tenant provisioning and auth user creation)
- `src/routes/auth.tsx` (Current login screen with Direct Access button)
- `src/routes/_authenticated/route.tsx` (Route guard with demo_mode bypass)
- `src/lib/auth.ts` (useCurrentUser hook with demo_mode fallback and hardcoded Nextgen Realty fallback)
- `src/lib/crm-data.ts` (useClient query and tenant data fetching)
- `src/routes/_authenticated/dashboard.tsx` (CRM dashboard header and tenant title)
