## 3. Submodule Architecture

The serverless codebase was restructured into 4 decoupled, independently testable submodules:

```
supabase/functions/realtor-lead-engine/
├── voice_decoder.ts           # ~220 lines: Audio buffer retrieval (Telegram/WhatsApp) & Groq Whisper/Gemini STT
├── cognitive_extractor.ts     # ~470 lines: Gemini 2.5 Flash/Pro JSON Schema extraction & Pro auto-escalation
├── multilingual_synthesizer.ts # ~320 lines: 22-language profile engine, Indic synthesis & regional fallback
├── verifier_gate.ts           # ~330 lines: Pre-flight self-correction gate & 4 invariant validators
└── index.ts                   # Request router, tenant resolution, FSM state orchestration & dispatch
```

### Invariants Enforced by `verifier_gate.ts`:
1. **Contradiction Invariant:** Detects and corrects intent polarity clashes (e.g., user says *"shop bechni he"* but bot asks buyer intake questions; or user says *"nahi aa sakta"* but bot confirms scheduled attendance).
2. **Redundancy Invariant:** Detects and eliminates repeated questions for entities already explicitly provided by the user (location, property type/BHK, budget). Auto-advances the dialog to the next missing qualification field.
3. **Hallucination Invariant:** Intercepts ungrounded ROI / "100% guarantee" promises and phantom bolded project titles not present in the catalog context.
4. **Policy & HTML Safety Invariant:** Enforces WABA anti-spam standards and automatically balances unclosed HTML tags (`<b>`, `<i>`, `<a>`, `<code>`) to eliminate Telegram HTTP 400 Bad Request dispatch failures.
