# Plan 6.1: Multi-Persona AI Conversation Summary & Comprehensive FSM State Explainer

<objective>
Transform the AI Conversation Summary in the CRM Dashboard into an intelligent, multi-persona briefing engine that accurately represents Property Sellers/Owners, Buyers, and Dual-Role clients with an exhaustive, human-readable explanation for all 20+ finite state machine (FSM) states.

Purpose:
Currently, `buildLeadSummary` in `src/lib/crm.ts` only treats leads as buyers (e.g., "Manthan ji property mein interested hain"), completely ignoring property submissions, seller details (project name, carpet area, expected demand, possession status), and owner intake stages. Sales reps and admins opening the drawer cannot see the seller's property or the exact stage of the conversation.

Output:
- Enhanced `buildLeadSummary(lead: Lead, submissions?: PropertySubmission[]): ReactNode` in `src/lib/crm.ts`.
- Integrated `lead-drawer.tsx` and `budget-tab.tsx` rendering the new multi-persona briefing.
</objective>

- `src/components/crm/budget-tab.tsx` (lead insights collapsible line 664)

</context>

    1. Detect Persona:
       - Dual Role (`isDualRoleLead(lead) || (submissions && submissions.length > 0 && (lead.property_type || lead.budget))`):
         Render a structured two-part briefing with clear Apple-styled visual separation:
         - **Seller/Listed Section**: Property configuration (e.g. "Villa"), Society/Project ("Spring field"), Location ("Waghodia Road"), Carpet/Built-up area ("900 sq.ft Carpet"), Commercials ("₹60 Lakhs Demand" or "₹25,000/mo Rent"), Specs (Ready to Move, Unfurnished), and Verification Status ("Pending Verification", "Verified", or "Added to Inventory").
         - **Buyer Section**: Seeking to Buy/Rent (e.g. "3BHK Flat"), Location, Budget ("₹50 Lakhs"), Purpose (Self-use/Investment), Timeline, and Shortlisted/Booked Property ("Pearl Heights" with site visit date & time).
       - Pure Owner/Seller (`lead.lead_type === 'PROVIDER' || lead.state?.startsWith('OWNER_') || (submissions && submissions.length > 0 && !lead.property_type && !lead.budget)`):
         Render Owner Listing briefing:
         - Heading: "[Name] ji apni property bechna chahte hain" (SELL) or "rent par dena chahte hain" (RENT).
         - Full property attributes extracted from `submissions[0]` or `lead.metadata.owner_draft`.
         - Stage explanation for intake states:
           - OWNER_CONFIG_PENDING: "Property configuration (Flat/Villa/Office/Shop) gather ki ja rahi hai."
           - OWNER_SOCIETY_PENDING: "Society / Project name enter hona baaki hai."
           - OWNER_LOCATION_PENDING: "Locality / Area details ka wait hai."
           - OWNER_AREA_PENDING / OWNER_SIZE_PENDING: "Carpet / Built-up area enter hona baaki hai."
           - OWNER_PRICE_PENDING: "Expected price / rent quote maangi ja rahi hai."
           - OWNER_POSSESSION_PENDING: "Possession status (RTM vs UC) confirm hona baaki hai."
           - OWNER_FURNISHING_PENDING: "Furnishing status confirm hona baaki hai."
           - OWNER_PHONE_PENDING: "Direct calling number verify ho raha hai."
           - OWNER_DETAILS_GATHERED / Completed: "Listing details complete — Admin verification desk par review ke liye queue mein hai."
       - Pure Buyer/Seeker:
         Render Buyer briefing:
         - Looking to Buy/Rent [Property Type] in [Location] with budget [Budget].
         - Shortlisted options, VIP Site visit schedule, and follow-up count.
    2. Comprehensive FSM State Explainer Matrix:
       Map every state to precise, actionable Hinglish descriptions:
       - `FRESH`, `NEW`, `ROLE_SELECTION_PENDING`
       - `DUAL_ROLE_MENU_PENDING`, `QUALIFYING`, `OPTIONS_SENT`, `CRITERIA_CONFIRMATION_PENDING`, `VISIT_REQUESTED`
       - `SITE_VISIT_BOOKED`, `VISIT_RESCHEDULED`, `SITE_VISIT_DONE`, `VISIT_MISSED`, `VISIT_CANCELLED`
       - All 9 `OWNER_*` intake states
       - `NEGOTIATING`, `DEAL_WON`, `NOT_INTERESTED`, `DROPPED`
    AVOID: Returning plain unformatted paragraphs that mash buyer and seller details together. Use distinct semantic fragments with bold key indicators.
