# Plan 4.8: In-Drawer Role Switcher, 1-Tap Manual Owner Listing Studio & Dual-Source Property Matchmaker

<objective>
Empower CRM sales executives to manage multi-persona clients seamlessly:
1. Provide an Apple HIG Persona Switcher (`[👤 Buyer] [🏷️ Seller] [🌟 Dual Role]`) inside the Lead Detail Drawer.
2. Provide a 1-tap `+ Add Seller Listing` modal allowing sales executives to list a client's property directly into `property_submissions` without requiring the client to message the bot.
3. Upgrade the Lead Drawer property matchmaker to search BOTH developer `inventory` and verified owner `property_submissions`, surfacing exclusive `[Verified Owner Resale 🔑]` opportunities.
</objective>

<context>
- Phase 4 previously established backend FSM dual-role transitions and CRM badges (Plans 4.1-4.7).
- Currently, `property_submissions` can only be created via the WhatsApp/Telegram bot. If a client phones an executive and asks to list their apartment for resale, there is no manual CRM entry point.
- `src/lib/crm-data.ts` currently provides `usePropertySubmissions`, `useApprovePropertySubmission`, and `useUpdatePropertySubmission`, but lacks `useCreatePropertySubmission`.
- In `src/components/crm/lead-drawer.tsx`, `matchingProperties` only filters `inventory` and ignores owner resale listings in `property_submissions`.
- Strict Non-n8n Architecture & 0 Extra Runtime JS Packages invariant.
</context>

  <files>src/lib/crm-data.ts, src/components/crm/add-property-listing-modal.tsx</files>
  <action>
    1. In `src/lib/crm-data.ts`:
       - Export `useCreatePropertySubmission()` mutation:
         - Inserts new row into `property_submissions` with `client_id`, `lead_id`, `owner_name`, `owner_phone`, `society_name`, `project_name`, `property_category`, `configuration`, `carpet_area_sqft`, `super_built_up_sqft`, `expected_price`, `expected_rent`, `transaction_type`, `furnishing_status`, `possession_status`, `location`, `status: "PENDING_VERIFICATION"`, `notes`.

         - Logs audit event in `lead_activity` table: `"Added new seller property listing at ${society_name}"` with `actor_type: "SALES_REP"`.
         - Invalidates query keys: `["property_submissions", clientId]`, `["leads", clientId]`, `["leads"]`.

    2. Create `src/components/crm/add-property-listing-modal.tsx`:
       - Apple HIG Dialog with frosted backdrop and continuous squircle curvature.
       - Pre-populates owner name, phone, and client_id from current `lead`.
       - Fields:
         - Category: Segmented toggle (`Flat`, `Villa`, `Commercial`, `Plot`)
         - Society / Project Name & Locality input
         - Configuration dropdown (`1BHK`, `2BHK`, `3BHK`, `4BHK`, `5BHK`, `Penthouse`, `Office`, `Shop`)
         - Transaction Type: (`Sale`, `Rent`)
         - Carpet Area (sq.ft) and Expected Price (₹ Lakhs/Crores) or Monthly Rent
         - Furnishing Status: (`Unfurnished`, `Semi-Furnished`, `Fully Furnished`)
         - Executive Notes
       - Validates required fields (Society, Configuration, Expected Price/Rent) with clear toast feedback.
       - On submit: triggers `createSubmissionMutation`, closes modal, and displays success toast: `"Property listing added successfully! Client upgraded to Dual-Role 🌟"`.
