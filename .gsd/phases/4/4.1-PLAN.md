# Plan 4.1: Dual-Persona Data Model, FSM Transitions, and Dual-Reminder Disambiguation Menu

## Objective
Implement Option A (Multi-Persona Lead Model) and Scenario 3 (Dual-Reminder Disambiguation Menu) in `supabase/functions/realtor-lead-engine/index.ts`. Enable a single lead to seamlessly operate as both a Property Seeker (Buyer/Tenant) and a Property Provider (Seller/Landlord). Guarantee zero criteria wipes when crossing roles, persist seller properties in `property_submissions`, and provide an intelligent dual-reminder greeting menu for returning multi-role clients.

    3. Dual-Role Transition Logic from Buyer States (`SITE_VISIT_BOOKED`, `OPTIONS_SENT`, `QUALIFIED`):
       - When an active seeker indicates intent to sell/rent out (`SUBMIT_LISTING` or seller keywords), preserve buyer criteria (`budget`, `location`, `property_type`, `site_visit_at`, `selected_property_id`).
       - Mark `lead_type: "DUAL_ROLE"` and set `metadata.has_buyer_profile: true`, `metadata.active_persona: "SELLER"`.
       - Hand over smoothly to `handleOwnerFlow`.

    4. Scenario 3 Dual-Reminder Greeting Disambiguation Menu:
       - In `dispatchStateAction()`, when `intent === "GREETING"`:
         Query `property_submissions` for the lead.
         If the lead has BOTH an active site visit (or active buyer criteria) AND submitted property listings:
         Construct the contextual Scenario 3 Dual-Reminder message:
         - Acknowledge upcoming visit: project name and scheduled IST time.
         - Acknowledge listed property: society name and review status (`Pending Verification` / `Under Review`).
         - Present 3-option disambiguation menu:
           `1️⃣ Site Visit / Property Search 🏡`
           `2️⃣ Meri Listed Property Status 📋`
           `3️⃣ Senior Advisor se call chahiye 📞`
         - Transition to `DUAL_ROLE_MENU_PENDING`.

    5. State Handler for `DUAL_ROLE_MENU_PENDING`:
       - Option 1 ("1", "1️⃣", "visit", "search", "option 1"): Anchor back to buyer state (`SITE_VISIT_BOOKED` if visit active, else `OPTIONS_SENT` or `QUALIFYING`).
       - Option 2 ("2", "2️⃣", "listed", "status", "property", "option 2"): Return verification status of their listed property and offer to list another property.
       - Option 3 ("3", "3️⃣", "call", "advisor", "senior", "option 3"): Dispatch `HIGH_VALUE_DUAL_ROLE` sales alert with pitch hints for senior partners, reply confirming high-priority callback.
       - Any explicit property text (e.g. "3BHK flat dikhao"): Route directly to `handleQualificationCascade` without dropping context.

    AVOID: Overwriting `lead_type` to a single role or deleting columns when switching personas.
    AVOID: Modifying any n8n workflows.
