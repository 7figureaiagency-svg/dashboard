# Plan 4.3: Robust Natural Slot Booking & FSM Anti-Reset Safeguard in OPTIONS_SENT

<objective>
Fix critical conversational defect where Telegram user 5117510624 replied "Aaj 6 baje" after receiving property options, but the agent failed to book the site visit and instead reset the conversation back to `ROLE_SELECTION_PENDING` ("Kripya batayein aap kis type ki property search kar rahe hain"). 

Ensure natural date/time slots in `OPTIONS_SENT` reliably book site visits under both AI classification and deterministic fallback, eliminate destructive state resets, and deploy Edge Function `v62-slot-booking-engine`.
</objective>

<context>
- Lead: `5117510624` (Manthan) in Supabase `leads` table.
- User previously received options for 3BHK flat in Vasna-Bhayli Road (Budget: 36k, Selected Property: `PROP-NXG-011` Vihav Skyline Residences).
- When user replied "Aaj 6 baje", the LLM timed out / failed, falling back to `DETERMINISTIC_FALLBACK`.
- Deterministic fallback lacked slot detection, defaulting to `GENERAL_QUERY`.
- `dispatchStateAction` for `OPTIONS_SENT` required `intent === "BOOK_VISIT"`. Since intent was `GENERAL_QUERY`, it fell through to the global catch-all, resetting state to `ROLE_SELECTION_PENDING`.
- Strict Non-n8n architecture rule: all logic lives in `supabase/functions/realtor-lead-engine/index.ts`.
</context>

  <name>Task 1: Add Slot Intent Classification & OPTIONS_SENT Booking Safeguard</name>
  <files>supabase/functions/realtor-lead-engine/index.ts</files>
  <action>
    1. Update `INTENT_CLASSIFICATION_SYSTEM_PROMPT` & `buildLeadContextForClassifier`:
       - Add few-shot exemplars:
         `"aaj 6 baje"` -> `{"action": {"intent": "BOOK_VISIT", "preferred_date_raw": "aaj", "preferred_time_raw": "6 baje"}, "language": "HINGLISH", "user_role": "SEEKER"}`
         `"kal shaam 5 baje"` -> `{"action": {"intent": "BOOK_VISIT", "preferred_date_raw": "kal", "preferred_time_raw": "shaam 5 baje"}, "language": "HINGLISH", "user_role": "SEEKER"}`
       - In `buildLeadContextForClassifier`: when `lead.state === "OPTIONS_SENT"`, explicitly declare:
         `Bot Question Waiting For: VISIT_SLOT_OR_OPTION_SELECTION (Bot sent property cards. Any date, time, day, or 'Option N' is strictly BOOK_VISIT or SELECT_OPTION!)`.

    2. Update `classifyLeadIntent` (Tier 3 Deterministic Fallback):
       - Detect natural time and date slots using regex:
         `/\b(aaj|kal|kale|today|tomorrow|sunday|monday|tuesday|wednesday|thursday|friday|saturday|parso|\d{1,2}(?::\d{2})?\s*(?:am|pm|baje|vage))\b/i`
       - If lead is in `OPTIONS_SENT` or `VISIT_REQUESTED` and message contains a slot pattern:
         Map `fallbackIntent = "BOOK_VISIT"`, setting `preferred_date_raw = messageText`.

    3. Update `dispatchStateAction` under `currentState === "OPTIONS_SENT"`:
       - Check `if (intent === "BOOK_VISIT" || hasSlotKeywords)` where `hasSlotKeywords` inspects for day/time tokens (`aaj`, `kal`, `baje`, `pm`, etc.).
       - If slot keywords are present, extract slot via `parseVisitSlot(slotRaw)`:
         - Resolve property ID: if `selected_property_id` is present, use it. If not, default to `last_option_ids[0]`.
         - Book visit: insert record into `site_visits`, update lead with `site_visit_booked: true`, `site_visit_at: scheduledAt`, `state: "SITE_VISIT_BOOKED"`.
         - Dispatch `SITE_VISIT_BOOKED` sales alert with rich property details and formatted time.
         - Send enthusiastic confirmation reply:
           `"Badhai ho ${nameStr}! 🎉 Aapki VIP Site Visit ${formatted} ke liye confirm ho gayi hai! 🚗 Milte hain site par!"`
       - Anti-Reset Guard: If an unrecognized non-booking message arrives in `OPTIONS_SENT`, DO NOT fall through to `ROLE_SELECTION_PENDING`. Remain in `OPTIONS_SENT` and politely remind the user:
         `"Aap inme se kis option ki VIP Site Visit schedule karna chahte hain, aur kaunsa time aapke liye best rahega (jaise 'Kal shaam 5 baje')? 🚗"`

    4. Bump Edge Function version to `v62-slot-booking-engine`.
