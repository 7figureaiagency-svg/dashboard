# Plan 9.2: Frontend Explicit Client-Scoped Queries & Cache Partitioning in CRM Hooks & Dashboard

## Objective
Enforce client-wise data partitioning in the React frontend application by updating `src/lib/crm-data.ts` to accept `clientId` in all queries and helper lookups (`useLeads`, `useInventory`, `useExecutives`, `useActivity`, `usePropertySubmissions`), disabling queries when `clientId` is null/loading (`enabled: !!clientId`), partitioning TanStack Query cache keys with `clientId`, and wiring `clientId` throughout `src/routes/_authenticated/dashboard.tsx`.

## Tasks

<task type="auto">
  <name>Task 1: Partition All CRM Queries, Mappers, and Cache Keys by `clientId` in `crm-data.ts`</name>
  <files>
    src/lib/crm-data.ts
  </files>
  <action>
    1. In `src/lib/crm-data.ts`:
       - Update `fetchExecutivesMap(clientId?: string | null)`:
         - If `!clientId`, return empty Map.
         - Filter query with `.eq("client_id", clientId)`.
       - Update `fetchInventoryLiteMap(clientId?: string | null)`:
         - If `!clientId`, return empty Map.
         - Filter query with `.eq("client_id", clientId)`.
       - Update `useLeads(clientId?: string | null)`:
         - `queryKey: ["leads", clientId]`: Cache key includes `clientId` so switching accounts never serves stale cache.
         - `enabled: !!clientId`: Do not execute query before the user's `clientId` is loaded.
         - Add `.eq("client_id", clientId)` to `supabase.from("leads").select("*")`.
         - Pass `clientId` to `fetchExecutivesMap(clientId)` and `fetchInventoryLiteMap(clientId)`.
       - Update `useInventory(clientId?: string | null)`:
         - `queryKey: ["inventory", clientId]`
         - `enabled: !!clientId`
         - Add `.eq("client_id", clientId)` to `supabase.from("inventory").select("*")`.
         - Pass `clientId` to `fetchExecutivesMap(clientId)`.
       - Update `useExecutives(clientId?: string | null)`:
         - `queryKey: ["executives", clientId]`
         - `enabled: !!clientId`
         - Add `.eq("client_id", clientId)` to `supabase.from("executives").select("*")`.
       - Update `useActivity(clientId?: string | null)`:
         - `queryKey: ["lead_activity", clientId]`
         - `enabled: !!clientId`
         - Filter `lead_activity` and `lead_events` by `.eq("client_id", clientId)`.
         - Pass `clientId` to `fetchExecutivesMap(clientId)`.
       - Update `usePropertySubmissions(clientId?: string | null)`:
         - `queryKey: ["property_submissions", clientId]`
         - `enabled: !!clientId`
         - Add `.eq("client_id", clientId)` to `supabase.from("property_submissions").select("*")`.
       - Update `useClientIntegrations(clientId?: string | null)`:
         - `queryKey: ["client_integrations", clientId]`
         - `enabled: !!clientId`
         - Add `.eq("client_id", clientId)` to query.
       - Update `useAddLead()` / `useSaveProperty()`:
         - Ensure new records explicitly attach `client_id: clientId` if not already set.

    AVOID: Defaulting `clientId` to Nextgen Realty when undefined.
    USE: `enabled: !!clientId` so queries pause gracefully during authentication resolution.
  </action>
  <verify>
    Run `npm.cmd run build` to verify TypeScript compiles cleanly.
  </verify>
  <done>
    All query hooks and helper functions in crm-data.ts require and filter by clientId, with cache keys cleanly partitioned.
  </done>
</task>
