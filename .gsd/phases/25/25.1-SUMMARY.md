## 1. Overview & Objectives

In Phase 25, Plan 25.1 resolves the critical Telegram bot bug where owner declarations like `"muje meri shop bechni he"` resulted in the bot falsely extracting `"Muje meri he"` as the Project/Society Name and jumping directly to asking for the Area/Location:
1. Implemented `isLikelySocietyOrProjectName(name: string): boolean` backed by a comprehensive dictionary of pronouns, conversational stop words, property types, and intent verbs to reject candidate names composed purely of conversational filler.
2. Refactored `extractProjectOrSocietyFromText` and `formatSocietyName` to strip property subtype keywords (`shop`, `office`, `flat`, `duplex`, etc.) and filter all candidates through `isLikelySocietyOrProjectName`.
3. Aligned `handleOwnerFlow` so that when a property type is recognized without a project name (e.g. `Commercial Shop`), it cleanly acknowledges the property type and prompts for the Commercial Complex / Business Hub (Step 2: `OWNER_SOCIETY_PENDING`) without skipping steps or fabricating names.
4. Added direct owner intent handoffs in `FRESH` and `ROLE_SELECTION_PENDING` states so first-message owner declarations seamlessly enter `handleOwnerFlow`.

## 2. Key Code Changes

### A. Strict Stop-Word & Validation Guard (`supabase/functions/realtor-lead-engine/index.ts`)
- Defined `STOP_WORDS_SET` covering:
  - Pronouns: `muje`, `mujhe`, `mane`, `mare`, `mari`, `maro`, `maru`, `meri`, `mera`, `mere`, `apni`, `apna`, `apne`, `i`, `my`, `we`, `our`, `me`, `us`, `humko`, `hume`, `hum`, `main`, `hu`, `ame`, `tame`, `aap`, `ek`, `ye`, `aa`, `yeh`.
  - Intent / Verbs: `bechna`, `bechni`, `bechne`, `bechvu`, `vechvu`, `vechva`, `vechvo`, `sell`, `selling`, `list`, `listing`, `karna`, `karni`, `karne`, `karvu`, `karva`, `karo`, `want`.
  - Connectors / Auxiliary: `he`, `hai`, `h`, `hain`, `che`, `chhe`, `to`, `chahiye`, `joiye`, `ka`, `ki`, `ke`, `nu`, `no`, `ni`, `na`, `in`, `at`, `me`, `ma`, `par`, `pe`, `se`, `thi`, `as`, `aur`, `ane`, `and`, `is`.
  - Property types: `sho`, `shop`, `office`, `flat`, `apartment`, `duplex`, `penthouse`, `villa`, `bungalow`, `house`, `ghar`, `makan`, `plot`, `land`, `zamin`, `showroom`, `godown`, `warehouse`, `dukan`, `commercial`, `residential`, `property`, `project`, `society`, `name`.
- Created `isLikelySocietyOrProjectName(name: string): boolean` which splits the candidate into words and checks if any word outside `STOP_WORDS_SET` exists. If not, the candidate is discarded as conversational boilerplate.

### B. Upgraded `extractProjectOrSocietyFromText` and `formatSocietyName`
- In Step 5 of extraction, property tokens (e.g. `shop`, `office`, `flat`) are stripped in addition to canonical `parsedPropType`.
- Filler words are replaced and the output string is validated with `isLikelySocietyOrProjectName`.
- `formatSocietyName` strips leading pronouns (`ye`, `meri`, `mera`, `maro`, `mari`, `muje`, `in`, `at`) and returns `""` if `!isLikelySocietyOrProjectName(cleaned)`.

### C. First-Turn Owner Flow Handoff
- In `currentState === "FRESH"`: Added `isFirstMessageOwner` detection routing directly to `handleOwnerFlow`.
- In `currentState === "ROLE_SELECTION_PENDING"`: Forwarded detected property types directly to `handleOwnerFlow` with pre-filled `draft.property_type`.
