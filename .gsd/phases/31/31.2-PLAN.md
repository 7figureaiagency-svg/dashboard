# Plan 31.2: Live Inventory Synchronization & Owner Intake Safeguards

## Objective
1. Ensure Owner Submissions approved or marked "CONVERTED_TO_INVENTORY" are 100% synchronized into the `inventory` table and immediately searchable:
   - When an admin saves `EditOwnerSubmissionDialog` with status `"CONVERTED_TO_INVENTORY"`, automatically upsert/insert the property into `inventory`.
   - When an already converted submission is edited in CRM (e.g. location changed from Bhayli to Alkapuri, price updated, etc.), automatically propagate the changes to the corresponding row in `inventory`.
   - Backfill/Repair data: Ensure Ramnath Complex (`99bb5b34-8870-4358-9190-18b75d5b608c`) is inserted into `inventory`, and Saraswati Bungalows (`OWNER-3BHK-MVSGTBE9`) location is updated to `Alkapuri` in `inventory`.
2. Safeguard Owner Intake flow:
   - If user inputs numeric measurement like `2000` when asked for Location/Landmark, do NOT save `location = '2000'`. Instead save it as carpet area and re-prompt for Area/Landmark.
   - If user inputs rent-per-month (e.g. `30k per month`) when asked for expected price, recognize it as rental/lease demand, set `transaction_type = 'RENT_OUT'` / `'LEASE'`, store `expected_rent = 30000`, and proceed to the next question rather than looping on "Expected Selling Price".

### Task 2: Owner Intake Safeguards: Numeric Location Trap & Rent-per-Month Disambiguation
<files>
supabase/functions/realtor-lead-engine/index.ts
</files>
<action>
1. In `supabase/functions/realtor-lead-engine/index.ts` inside Owner Listing Intake (`handleOwnerListingIntake`):
   - At `OWNER_LOCATION_PENDING`:
     - Check if user's input is a numeric area measurement (e.g. `2000`, `1250 sqft`, `1500 var`):
       - If yes: do NOT set `location = userText`. Instead set `ownerDraft.carpet_area_sqft = parsedArea` (or `plot_area`), and re-prompt for the physical Area/Landmark:
         - Hinglish: `Noted ${parsedArea} sq.ft! Lekin ye property kaunse Area ya Landmark ke paas sthit hai? 📍`
         - Gujlish: `Noted ${parsedArea} sq.ft! Pan aa property kaya Area ke Landmark pase chhe? 📍`
   - At `OWNER_PRICE_PENDING`:
     - Check if user's response specifies rent (e.g. `30k per month`, `30000/mo`, `bhadu 25000`, `rent 20k`):
       - If rent detected:
         - Parse numeric rent amount (e.g. `30000`).
         - Set `ownerDraft.transaction_type = 'RENT_OUT'` / `'LEASE'`, `ownerDraft.expected_rent = 30000`.
         - If furnishing was also mentioned (e.g. `semi furnished he`), extract `furnishing_status = 'SEMI_FURNISHED'`.
         - Transition to next stage (`OWNER_AMENITIES_PENDING` or `OWNER_DETAILS_GATHERED`) without looping on "Expected Selling Price".
</action>
<verify>
Run scratch test:
1. When in `OWNER_LOCATION_PENDING`, inputting "2000" does NOT set location="2000", saves carpet area 2000, and re-asks location.
2. When in `OWNER_PRICE_PENDING`, inputting "30k per month and semi furnished he" transitions to next stage with `expected_rent: 30000` and `furnishing_status: "SEMI_FURNISHED"`.
</verify>
<done>
Numeric location trap is blocked and rent-per-month owner submissions proceed smoothly without loops.
</done>
