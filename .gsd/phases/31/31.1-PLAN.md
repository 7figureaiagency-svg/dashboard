# Plan 31.1: India-Wide City Disambiguation & Currency/Number Parsing Fix

## Objective
1. Handle any Indian city (Vadodara, Ahmedabad, Surat, Mumbai, Delhi, Bengaluru, Pune, etc.) when mentioned by the user:
   - Recognize city names as `CITY` entities, preventing accidental mapping to specific local areas.
   - Guard `extractLocationFromText` so it NEVER matches a property landmark that happens to contain the city name (e.g. landmark "Vadodara Central" under Alkapuri must never match user text "Vadodara").
   - If the user names the tenant's primary city (e.g. Vadodara), acknowledge the city and prompt for the specific preferred area/locality within that city.
   - If the user names a city outside the tenant's service area, politely clarify the tenant's primary operating region and ask if they are looking to invest in the tenant's city.
2. Fix number & currency parsing glitches:
   - Correct `parseBudgetFromText` so `1 cr` / `1 crore` is parsed as `10,000,000` (1 Crore = 10 Million), NOT `100,000,000` (10 Crore).
   - Eliminate double rupee symbol `₹₹` across all dynamic templates in `realtor-lead-engine/index.ts` so all amounts display cleanly as `₹15,000`, `₹1 Cr`, etc.
