# Plan 24.1: Database RLS Executive Hardening & Admin-Only Property Governance

## Objective
Apply database-level Row-Level Security (RLS) to enforce two critical access control invariants discovered in the Phase 24 E2E QA Audit:
1. Sales executives can only view and update their own assigned leads — not any other executive's leads in the same tenant.
2. The `property_submissions` table is strictly Admin-only — no SELECT, UPDATE, or DELETE access for any non-admin role at the database layer.

This closes BUG-01 [P1] (executive lead data leak) entirely at the PostgreSQL layer, eliminating the frontend-only filter bypass.

## Context
Load these files for context:
- supabase/migrations/ (all existing migration files)
- src/lib/crm.ts (type definitions)
- src/lib/crm-data.ts (useApprovePropertySubmission)
- .gsd/STATE.md

Key constraint: The QA audit confirmed that `leads` RLS only checks `client_id`. Executive-level filtering is done exclusively in the React frontend and can be bypassed via Supabase JS client in the browser console.

  <action>
    Create the migration file with these steps:

    1. Add `user_id uuid references auth.users(id)` column to `public.executives` (if not already present):
       ```sql
       DO $$ BEGIN
         IF NOT EXISTS (
           SELECT 1 FROM information_schema.columns 
           WHERE table_name = 'executives' AND column_name = 'user_id'
         ) THEN
           ALTER TABLE public.executives ADD COLUMN user_id uuid REFERENCES auth.users(id);
         END IF;
       END $$;
       ```

    2. Create security definer function `public.current_executive_id()` that returns the UUID of the currently authenticated executive by matching `auth.uid()` to `executives.user_id` OR phone-based fallback:
       ```sql
       CREATE OR REPLACE FUNCTION public.current_executive_id()
       RETURNS uuid LANGUAGE sql STABLE SECURITY DEFINER AS $$
         SELECT id FROM public.executives
         WHERE user_id = auth.uid()
         LIMIT 1;
       $$;
       ```

    3. Create security definer function `public.is_admin()`:
       ```sql
       CREATE OR REPLACE FUNCTION public.is_admin()
       RETURNS boolean LANGUAGE sql STABLE SECURITY DEFINER AS $$
         SELECT EXISTS (
           SELECT 1 FROM public.profiles
           WHERE id = auth.uid()::text AND role = 'admin'
         );
       $$;
       ```

    4. Drop and recreate `leads` RLS policies (SELECT and UPDATE):
       ```sql
       DROP POLICY IF EXISTS "dashboard_select_leads" ON public.leads;
       DROP POLICY IF EXISTS "dashboard_update_leads" ON public.leads;

       CREATE POLICY "dashboard_select_leads" ON public.leads
       FOR SELECT TO authenticated
       USING (
         client_id = public.current_client_id() AND (
           public.is_admin()
           OR assigned_executive_id = public.current_executive_id()
           OR assigned_executive_id IS NULL
         )
       );

       CREATE POLICY "dashboard_update_leads" ON public.leads
       FOR UPDATE TO authenticated
       USING (
         client_id = public.current_client_id() AND (
           public.is_admin()
           OR assigned_executive_id = public.current_executive_id()
           OR assigned_executive_id IS NULL
         )
       )
       WITH CHECK (
         client_id = public.current_client_id() AND (
           public.is_admin()
           OR assigned_executive_id = public.current_executive_id()
           OR assigned_executive_id IS NULL
         )
       );
       ```

    5. Drop and recreate `property_submissions` RLS policies — STRICT ADMIN ONLY:
       ```sql
       DROP POLICY IF EXISTS "dashboard_select_property_submissions" ON public.property_submissions;
       DROP POLICY IF EXISTS "dashboard_update_property_submissions" ON public.property_submissions;
       DROP POLICY IF EXISTS "dashboard_delete_property_submissions" ON public.property_submissions;
       DROP POLICY IF EXISTS "anon_select_property_submissions" ON public.property_submissions;

       CREATE POLICY "dashboard_select_property_submissions" ON public.property_submissions
       FOR SELECT TO authenticated
       USING (client_id = public.current_client_id() AND public.is_admin());

       CREATE POLICY "dashboard_update_property_submissions" ON public.property_submissions
       FOR UPDATE TO authenticated
       USING (client_id = public.current_client_id() AND public.is_admin())
       WITH CHECK (client_id = public.current_client_id() AND public.is_admin());

       CREATE POLICY "dashboard_delete_property_submissions" ON public.property_submissions
       FOR DELETE TO authenticated
       USING (client_id = public.current_client_id() AND public.is_admin());
       ```

    6. Apply the migration to the production Supabase project via `apply_migration` MCP tool.

    AVOID: Making any changes to Edge Function anon/service_role policies — they use service_role which bypasses RLS.
    USE: `SECURITY DEFINER` on helper functions so they run with elevated privileges to read `profiles`/`executives` tables.
