# Plan 39.2: AI Single-Source of Truth for Entity Extraction & Slot Filling

<objective>
Eradicate legacy regex slot parsers (`parseBudgetFromText`, `parsePropertyTypeFromText`, `extractLocationFromText`, `parseSlotDateTimeFromText`, `parseAreaFromText`, `parseFloorFromText`), ensuring all real estate entities (Budget in INR, BHK/Configuration, Geocoded Locality/City, Visit Slot, Carpet Area, Floor) are provided natively by the Gemini 2.0 Flash / Groq Cognitive Extractor with strict schema validation.
</objective>

<context>
- Currently, when AI finishes extraction, the code frequently executes fallback chains like:
  `const bVal = actionResult.price_or_budget || parseBudgetFromText(context.messageText);`
  `const pType = actionResult.property_type || parsePropertyTypeFromText(context.messageText);`
  `const locVal = actionResult.location || extractLocationFromText(context.messageText);`
- These regex functions contain fragile regexes that:
  - Falsely match numbers as budgets or floors as BHKs.
  - Falsely match cities (like "Vadodara") against landmark names ("Vadodara Central" -> Alkapuri).
  - Mishandle Indian measurement units (gaj, vigha, guntha, bigha vs sq.ft).
  - Break on vernacular time expressions ("ravivar sanje 5", "parso 11 vage").
- In Phase 39.2, we eliminate blind regex slot filling and enforce that `aiAnalysis.extracted.entities` supplies all values. The regex parsers will only remain as minimal deterministic fallbacks for offline testing and will never override AI decisions.
</context>
