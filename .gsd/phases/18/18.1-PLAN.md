# Plan 18.1: Post-Visit Lifecycle, Attendance Normalization & Objection Feedback Engine

<objective>
Fix two interconnected conversational and lifecycle defects in `realtor-lead-engine`:
1. When user sent "Mene visit kr di thi", `leadUpdates` included `status: "VISIT_DONE"`. Because the PostgreSQL `leads` table does not have a `status` column (only `state`), the update was rejected by Postgres, leaving `site_visit_booked: true` and failing to transition the lead to `SITE_VISIT_DONE`. Furthermore, proactive attendance declarations were bypassed if `post_visit_feedback_sent` was false.
2. When user subsequently sent "Layout accha nai laga. Front gate oe kenal he", `SITE_VISIT_DONE` had no handler for user feedback/objections. It fell through to the default catch-all, asking "Aap kis type ki property search kar rahe hain — Flat, Villa ya Commercial?" and resetting the lead to `ROLE_SELECTION_PENDING`.

Implement schema-safe lead updates, proactive natural language visit attendance detection, and an intelligent post-visit objection/feedback handler that preserves conversational context and alerts sales executives.
</objective>
