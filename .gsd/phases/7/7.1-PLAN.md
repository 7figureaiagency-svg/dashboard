# Plan 7.1: Multi-Portal Webhook Normalizer, Property Auto-Matcher & Instant WhatsApp Outreach

## Objective
Implement universal lead webhook ingestion in `supabase/functions/realtor-lead-engine/index.ts` for major Indian real estate portals (99acres, MagicBricks, Housing.com, CommonFloor, Facebook Lead Ads, and custom webhooks). Normalize varied portal payloads into a unified format, enforce 24-hour lead deduplication, automatically match requested inventory against live properties, trigger instant consultative Hinglish WhatsApp outreach with brochure PDF links and Google Maps pins, and transition lead state into `SITE_VISIT_PROPOSED` for seamless handoff to the conversational TypeChat FSM.

    3. In `supabase/functions/realtor-lead-engine/index.ts`:
       - Create a robust portal payload normalizer function `normalizePortalPayload(body: any, url: URL)`:
         - Detect source: check `url.searchParams.get("source")` or `url.searchParams.get("provider")`, or inspect payload signatures:
           - 99acres: contains `LeadId`, `Query`, `ProjectName`, `Mobile`, or `leadDetails`
           - MagicBricks: contains `customerName`, `locality`, `userComments`, or `leadId`
           - Housing.com: contains `lead_id`, `lead_name`, `lead_phone`, `lead_email`, `min_budget`, `max_budget`
           - CommonFloor: contains `contact_number`, `budget_max`, `project`
           - Facebook Lead Ads: contains `leadgen_id`, `form_id`, `field_data` array with `name` and `values`
           - Custom: standard `{ name, phone, email, project, budget, location, message }`
         - Normalize into a uniform object:
           ```ts
           interface NormalizedPortalLead {
             name: string;
             phone: string | null; // Sanitized 10-12 digits without symbols, or null if masked/empty
             email: string | null;
             source: string; // e.g. "99acres", "MagicBricks", "Housing.com", "CommonFloor", "Facebook", "Custom"
             projectName: string | null;
             propertyType: string | null; // e.g. "Flat", "Villa", "Commercial"
             budget: number | null;
             location: string | null;
             userComments: string | null;
             rawPayload: any;
           }
           ```
         - Clean phone: remove spaces, hyphens, parentheses, extract 10-digit Indian mobile. If landline (starting with 0265, 022, etc.), masked with asterisks ("98250*****"), or null/empty, set `phone: null`.
       - Wire normalizer in the main `Deno.serve` handler:
         - Check if incoming request is a portal webhook (either `url.searchParams.has("source")` or payload matches portal signature and is NOT Telegram or WhatsApp Cloud API webhook).
         - Resolve `activeTenantId` from `url.searchParams.get("client_id")`, `body.client_id`, or `body.tenant_id`, fallback to `defaultTenantId`.
       - Implement 24-Hour Deduplication:
         - If `normalized.phone` exists, query `leads` table for a lead with matching `phone` (or phone ending in the same 10 digits) created or updated within the last 24 hours under `client_id = activeTenantId`.
         - If no phone but `normalized.email` exists, match by email within last 24 hours.
         - If duplicate found:
           - Update existing lead record: append portal inquiry to `metadata.portal_inquiries`, update `last_interaction_at = now()`, retain existing state (do not reset if already QUALIFIED or SITE_VISIT_BOOKED).
           - Log `lead_events` with `event_type: "PORTAL_INQUIRY_MERGED"`.
         - If new lead:
           - Insert into `leads` table:
             - `lead_id`: `normalized.phone ? normalized.phone : "portal_" + crypto.randomUUID().slice(0, 8)`
             - `client_id`: `activeTenantId`
             - `first_name`: `normalized.name`
             - `phone`: `normalized.phone`
             - `source`: `normalized.source`
             - `property_type`: `normalized.propertyType`
             - `budget`: `normalized.budget`
             - `location`: `normalized.location`
             - `state`: `"FRESH"`
             - `bot_active`: `Boolean(normalized.phone)`
             - `metadata`: `{ portal_source: normalized.source, original_payload: normalized.rawPayload, user_comments: normalized.userComments, phone_missing: !normalized.phone }`
       - If `phone` is missing or masked:
         - Dispatch sales alert to Manager: `alertType = "UNASSIGNED_LEAD"` with hint: *"Portal inquiry from ${normalized.source} received without mobile number. Check portal inbox or call/email client."*
         - Return 200 JSON acknowledging ingestion `{ success: true, lead_id: lead.lead_id, status: "phone_missing_flagged" }`.

    AVOID: Overwriting existing lead state or booked visits when a repeat portal inquiry arrives.
    USE: Additive merging into `metadata.portal_inquiries` with timestamp.

<task type="auto">
  <name>Task 2: Inventory Auto-Matcher, Instant Consultative WhatsApp Outreach & FSM State Handoff</name>
  <files>
    supabase/functions/realtor-lead-engine/index.ts
  </files>
  <action>
    In `supabase/functions/realtor-lead-engine/index.ts`:
    1. Implement Property Auto-Matcher `matchInventoryForPortalLead(tenantId: string, leadInquiry: NormalizedPortalLead)`:
       - Query active inventory for `client_id = tenantId` and `status = 'AVAILABLE'`.
       - Matching Hierarchy:
         - Match 1 (Project Name): If `leadInquiry.projectName` is specified, perform case-insensitive fuzzy match against `project_name` in inventory.
         - Match 2 (Location + Configuration): If `leadInquiry.location` or `leadInquiry.propertyType` is specified, filter properties matching location substring and configuration/bhk.
         - Match 3 (Budget Corridor): Match properties where `price` is within ±30% of `leadInquiry.budget`.
         - Match 4 (Tenant Featured Default): Fallback to prime available property for this tenant.
       - Return matched property object (with `project_name`, `configuration`, `price`, `location`, `brochure_url`, `map_url`, `amenities`).

    2. Implement Instant Consultative Hinglish WhatsApp Outreach `dispatchPortalWhatsAppOutreach(tenantId: string, lead: any, property: any, source: string)`:
       - Ensure `lead.phone` is a valid mobile number (10 to 12 digits).
       - Query tenant's WhatsApp credentials from `clients` table (`whatsapp_phone_number_id`, `access_token` or env fallback).
       - Compose consultative Hinglish WhatsApp outreach message adhering to high-converting NextGen tone:
         ```
         Namaste {Name} ji! 🙏

         Humne {Source} par aapki inquiry dekhi regarding {ProjectName / PropertyType}.

         Main {AgencyName} se senior property advisor baat kar raha hu. Aapki requirement ke according hamara verified project:

         🏡 *{ProjectName}*
         📍 Location: {Location}
         📐 Configuration: {Configuration}
         💰 Price: {FormattedPrice}
         ✨ Highlights: {KeyAmenities}

         📄 *Project Brochure & Layouts:*
         {BrochureUrl}

         📍 *Google Maps Location:*
         {MapUrl}

         👉 Kya hum kal shaam 5 baje ya Sunday subah 11 baje aapki exclusive *VIP Site Visit 🚗* schedule karein?
         ```
       - Format with `formatForWhatsApp` to convert any Markdown/HTML to WhatsApp bold/italic styling.
       - Send message via `sendWhatsAppMessage(phoneNumberId, accessToken, formattedPhone, text)`.

    3. Handoff to TypeChat FSM & State Transition:
       - Update `leads` record:
         - `selected_property_id`: `property?.property_id || null`
         - `state`: `"SITE_VISIT_PROPOSED"`
         - `last_interaction_at`: `new Date().toISOString()`
         - `metadata`: `{ ...lead.metadata, selected_property_name: property?.project_name, portal_outreach_sent: true, portal_outreach_at: new Date().toISOString() }`
       - Log `lead_events` with `event_type: "PORTAL_OUTREACH_SENT"` and payload containing sent text and matched property.
       - Dispatch real-time sales alert to assigned executive or Sales Specialist:
         - `alertType = "NEW_PORTAL_LEAD"`
         - Badge: `🔥 NEW PORTAL LEAD (WHATSAPP OUTREACH SENT)`
         - Pitch hint: *"Portal inquiry converted to WhatsApp dialog. Lead is in SITE_VISIT_PROPOSED state. Keep sample keys ready."*
       - When the customer replies on WhatsApp (e.g. "Haan kal shaam 5 baje", "Yes Sunday"), the incoming message triggers the standard TypeChat conversational engine, where `state === "SITE_VISIT_PROPOSED"` smoothly parses the date/time and transitions to `SITE_VISIT_BOOKED`!

    AVOID: Hardcoding city or builder names. Dynamically inject tenant agency name, city, and brochure/map URLs.
    AVOID: Sending messages outside business hours if restricted, but for instant inbound inquiries, immediate transactional response within 60s is standard real estate SLA.
  </action>
