# Plan 3.1: Discriminated Union Schema & LLM Zero-Regex Prompt Engineering

## Objective
Elevate the conversational intent classification in `supabase/functions/realtor-lead-engine/index.ts` from loose JSON extraction into a TypeChat-style TypeScript Discriminated Union architecture. Define strict, strongly-typed schemas for user actions (`UserAction`), write a runtime schema validator (`validateUserAction`), and upgrade the micro-LLM system prompt with authentic multilingual few-shot exemplars (Indian English, Hinglish, Gujlish, and Gujarati script) to guarantee deterministic intent and entity extraction.

       - `HumanCallAction`: `{ intent: "REQUEST_HUMAN_CALL"; reason?: string | null; }`
       - `BrochureRequestAction`: `{ intent: "BROCHURE_REQUEST"; project_name?: string | null; }`
       - `MapRequestAction`: `{ intent: "MAP_REQUEST"; project_name?: string | null; }`
       - `MarketAdvisoryAction`: `{ intent: "MARKET_ADVISORY"; query?: string | null; }`
       - `GreetingAction`: `{ intent: "GREETING"; token?: string | null; }`

    2. Define `ClassifiedActionResult`:
       ```typescript
       interface ClassifiedActionResult {
         action: UserAction;
         user_role: "SEEKER" | "OWNER" | "UNKNOWN";
         language: "HINGLISH" | "GUJLISH" | "ENGLISH" | "GUJARATI_SCRIPT";
         provider_used: "GEMINI" | "GROQ" | "DETERMINISTIC_FALLBACK";
         latency_ms: number;
         raw_intent_name: string;
       }
       ```

    3. Implement runtime schema validator `validateUserAction(raw: any, leadState?: string): UserAction`:

       - Normalize 1-based ordinal numbers ("1", "option 1", "pehla") to 0-indexed integer `option_index`.
       - Clean and validate Indian 10-digit phone numbers for owner contacts.
       - Convert budget expressions (e.g. "50 Lakhs" -> 5000000, "1.5 Cr" -> 15000000).
       - Ensure fallbacks produce a mathematically valid `UserAction` without returning raw `undefined` or runtime exceptions.

    AVOID: Returning untyped `any` objects or loose dictionaries from LLM responses because downstream state dispatchers will silently fail or misroute.
    USE: Exhaustive switch / discriminated union type narrowing so TypeScript checks every branch at compile time.
