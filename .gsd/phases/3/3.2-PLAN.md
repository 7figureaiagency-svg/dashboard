# Plan 3.2: Deterministic State Transition Routing & Elimination of Fragile Regex Cascades

## Objective
Replace brittle cascading regular expressions and section-hijacking logic in `handleIncomingMessage()` with a deterministic Finite State Machine (FSM) router (`dispatchStateAction`). Route dialog transitions mathematically based on `(lead.state, validatedAction.intent)` to guarantee zero option hijacking, zero accidental criteria wipes, seamless returning-lead re-anchoring, and 100% Non-n8n architectural compliance.

       ```typescript
         | "OWNER_FURNISHING_PENDING"
         | "OWNER_PHONE_PENDING"
         | "OWNER_DETAILS_GATHERED"
         | "DROPPED";

       interface DialogTransitionResult {
         replyText: string;
         nextState: DialogState;
         leadUpdates?: Record<string, any>;
         salesAlert?: { type: string; payload?: Record<string, any> };
       }
       ```

    2. Implement `dispatchStateAction(lead: any, actionResult: ClassifiedActionResult, context: DialogContext): Promise<DialogTransitionResult>`:
       - **State `ROLE_SELECTION_PENDING`**:
         - `SELECT_OPTION` with index 0, or `intent: "CHANGE_REQUIREMENT"` -> Transition to `QUALIFYING` as `lead_type: "SEEKER"`.
         - `SELECT_OPTION` with index 1, or `intent: "SUBMIT_LISTING"` -> Transition to `OWNER_CONFIG_PENDING` as `lead_type: "PROVIDER"`.
       - **State `OPTIONS_SENT`**:
         - `SELECT_OPTION`: Anchor `selected_property_id` to `lead.last_option_ids[action.option_index]`. If another visit is already booked, transition to `CANCEL_PREVIOUS_VISIT_CONFIRMATION_PENDING`. Otherwise prompt for visit slot ("Kal shaam 5 baje ya Sunday subah 11 baje").
         - `BOOK_VISIT`: Resolve property (from index, project name, or active anchor), validate slot (10 AM - 6 PM IST), insert into `site_visits`, transition to `SITE_VISIT_BOOKED`.
         - `CHANGE_REQUIREMENT`: Wipe prior search, transition to `QUALIFYING` with new criteria.
         - `ASK_FAQ`: Fetch property specifications from DB, reply with answers, attach VIP Site Visit conversion CTA bridge without changing state.
         - `BROCHURE_REQUEST` / `MAP_REQUEST`: Send official link for property without dropping out of `OPTIONS_SENT`.
       - **State `CRITERIA_CONFIRMATION_PENDING`**:
         - `CONFIRM_CRITERIA` (confirm: true) or `SELECT_OPTION` (index 0): Retain criteria, query unseen inventory, transition to `OPTIONS_SENT`.
         - `CONFIRM_CRITERIA` (confirm: false), `SELECT_OPTION` (index 1), or `CHANGE_REQUIREMENT`: Cleanly wipe prior criteria, transition to `QUALIFYING` (or `ROLE_SELECTION_PENDING` if completely fresh).
       - **State `SITE_VISIT_BOOKED` / `VISIT_RESCHEDULED`**:
         - `GREETING`: Welcome back, display booked property name, location, and scheduled time, remind "Milte hain site par". Never drop to qualifying.
         - `RESCHEDULE_VISIT`: Parse new slot, validate working hours, update `site_visits`, transition to `VISIT_RESCHEDULED`.
         - `CANNOT_ATTEND_VISIT`: Set state `VISIT_MISSED`, mark `site_visits` status `MISSED`, dispatch sales alert, and prompt alternative reschedule slots with empathy.
         - `CANCEL_VISIT`: Cancel appointment in `site_visits`, set `VISIT_CANCELLED`, dispatch sales alert.
       - **State `SITE_VISIT_DONE`**:
         - `CONFIRM_VISIT_ATTENDANCE` / Feedback: Save feedback, handle negotiation/loan intent, advance nurture drip.
       - **State `VISIT_MISSED`**:
         - `RESCHEDULE_VISIT` / `BOOK_VISIT`: Reschedule appointment, update `site_visits` to `RESCHEDULED`, return to `SITE_VISIT_BOOKED`.

    3. Enforce Non-Negotiable Invariants:
       - **Zero Option Hijacking**: When state is `OPTIONS_SENT`, numbers 0/1/2 or "option 1/2/3" MUST NEVER trigger criteria changes or fall through into budget/phone parsers.
       - **Zero Criteria Wipe**: Existing requirements are NEVER erased unless the lead explicitly signals `CHANGE_REQUIREMENT` or answers "Change criteria" in confirmation.
       - **Zero Silent Drops**: If `replyText` is empty or whitespace, emit a contextual polite prompt based on `lead.state`.

    AVOID: Cascading nested `if/else-if` statements matching loose words; all state logic must flow through `dispatchStateAction()`.
    USE: Exhaustive typed state-transition branching with clear default fallback paths.
