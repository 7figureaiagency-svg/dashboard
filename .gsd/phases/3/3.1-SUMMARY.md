# Phase 3 Plan 1: Discriminated Union Schema & Zero-Regex Intent Classifier Summary

## Objective
Elevate the conversational intent classification in `supabase/functions/realtor-lead-engine/index.ts` from loose JSON extraction into a TypeChat-style TypeScript Discriminated Union architecture. Strongly typed schemas for user actions (`UserAction`), runtime schema validation (`validateUserAction`), and micro-LLM prompt engineering with authentic multilingual few-shot exemplars (Indian English, Hinglish, Gujlish, and Gujarati script).

## Changes Implemented

### 1. TypeScript Discriminated Union Schemas (`UserAction`)
Defined 18 distinct, strongly typed intent action interfaces in `supabase/functions/realtor-lead-engine/index.ts`:
- `BookVisitAction`: `{ intent: "BOOK_VISIT"; target_property_index?: number | null; target_property_name?: string | null; preferred_date_raw?: string | null; preferred_time_raw?: string | null; slot_iso?: string | null; }`
- `SelectOptionAction`: `{ intent: "SELECT_OPTION"; option_index: number; }` (normalized 0-indexed integer)
- `ChangeRequirementAction`: `{ intent: "CHANGE_REQUIREMENT"; property_type?: string | null; budget?: number | null; location?: string | null; requirement?: "BUY" | "RENT" | "LEASE" | null; is_flexible_location?: boolean; }`
- `ConfirmCriteriaAction`: `{ intent: "CONFIRM_CRITERIA"; confirm: boolean; }`
- `AskFaqAction`: `{ intent: "ASK_FAQ"; topic: "AMENITIES" | "RERA" | "LOAN" | "POSSESSION" | "BROKERAGE" | "LANDMARKS" | "PRICING_DISCOUNT"; specific_query?: string | null; }`
- `SubmitListingAction`: `{ intent: "SUBMIT_LISTING"; transaction_type?: "SELL" | "RENT_OUT" | null; property_type?: string | null; location?: string | null; project_or_society?: string | null; price_or_rent?: number | null; carpet_sqft?: number | null; super_built_up_sqft?: number | null; plot_area_sqft?: number | null; possession_status?: "READY_TO_MOVE" | "UNDER_CONSTRUCTION" | null; furnishing_status?: "FURNISHED" | "SEMI_FURNISHED" | "UNFURNISHED" | null; contact_phone?: string | null; }`
- `CancelVisitAction`: `{ intent: "CANCEL_VISIT"; reason?: string | null; }`
- `RescheduleVisitAction`: `{ intent: "RESCHEDULE_VISIT"; new_slot_raw?: string | null; }`
- `CannotAttendVisitAction`: `{ intent: "CANNOT_ATTEND_VISIT"; reason?: string | null; }`
- `ConfirmVisitAttendanceAction`: `{ intent: "CONFIRM_VISIT_ATTENDANCE"; attended: boolean; feedback?: string | null; }`
- `HumanCallAction`: `{ intent: "REQUEST_HUMAN_CALL"; reason?: string | null; }`
- `BrochureRequestAction`: `{ intent: "BROCHURE_REQUEST"; project_name?: string | null; }`
- `MapRequestAction`: `{ intent: "MAP_REQUEST"; project_name?: string | null; }`
- `MarketAdvisoryAction`: `{ intent: "MARKET_ADVISORY"; query?: string | null; }`
- `GreetingAction`: `{ intent: "GREETING"; token?: string | null; }`
- `OptOutAction`: `{ intent: "OPT_OUT"; }`
- `OffTopicAction`: `{ intent: "OFF_TOPIC"; }`
- `GeneralQueryAction`: `{ intent: "GENERAL_QUERY"; query: string; }`

### 2. Runtime Schema Validator (`validateUserAction`) & Backward Compatibility Bridge
- Implemented `validateUserAction(raw: any, leadState?: string): UserAction`:
  - Discards hallucinated or corrupted properties.
  - Normalizes 1-based and ordinal strings ("1", "first", "pehla", "option 1") to 0-indexed integers.
  - Sanitizes Indian 10-digit mobile phone numbers (strips +91 prefix and formatting characters).
  - Normalizes budget and price strings ("50 Lakhs", "1.5 Cr") to integer rupee values.
  - Guarantees valid `UserAction` object fallback without throwing runtime exceptions.
- Implemented `buildClassifiedActionResult()` and `ClassifiedActionResult` interface extending legacy bridge properties for backward-compatible consumption by existing callers.

### 3. TypeChat Multilingual System Prompt
- Updated `INTENT_CLASSIFICATION_SYSTEM_PROMPT` with the full TypeScript `UserAction` interface definition.
- Embedded 19 authentic multilingual few-shot exemplars across English, Hinglish, Gujlish, and Gujarati script.
- Upgraded `classifyLeadIntentWithGroq`, `classifyLeadIntentWithGemini`, and the deterministic fallback in `classifyLeadIntent` to pipe all raw payloads through `validateUserAction` and return typed `ClassifiedActionResult`.
