# Phase 3 Plan 3 (Gap Closure): Fix VISIT_CANCELLED Loop, Dual-Role Transition, and Catch-All Routing Summary

## Objective
Close conversational dead-ends where leads in `VISIT_CANCELLED` or `SITE_VISIT_BOOKED` get trapped in an infinite loop repeating `"Ji Manthan ji! Kripya batayein aap kis type ki property search kar rahe hain — Flat, Villa, ya Commercial Office/Shop? 🏡"`. Add explicit state handlers for `VISIT_CANCELLED` and `DROPPED`, enable seller/owner transitions from booked visits, make the catch-all forward to `handleQualificationCascade` if property attributes are present, and fix nested `<b><b>Name</b></b>` formatting.

## Changes Implemented

### 1. Explicit `VISIT_CANCELLED` and `DROPPED` State Handlers
- In `supabase/functions/realtor-lead-engine/index.ts`:
  - Added dedicated section `9b` for `currentState === "VISIT_CANCELLED"`:
    - Greets returning user with polite re-welcoming and offers fresh selection (Buyer/Tenant vs Seller/Owner), transitioning to `ROLE_SELECTION_PENDING`.
    - Automatically absorbs property search keywords/types (e.g. `"Office"`, `"Commercial"`, `"Flat"`), notes them, and transitions into `QUALIFYING` via `handleQualificationCascade()`.
    - Handles owner listing intent (`"Muje meri property sell krni he"`, `SUBMIT_LISTING`), routing to `handleOwnerFlow()`.
    - Supports rebooking or rescheduling cancelled visits into `site_visits`.
  - Added dedicated section `9c` for `currentState === "DROPPED"`:
    - Automatically reactivates bot (`bot_active: true`) on incoming user message and prompts role selection.

### 2. Dual-Role & Property Inquiry Support in `SITE_VISIT_BOOKED`
- When a lead with an active booked visit submits an owner listing request (`SUBMIT_LISTING` or `"bechna/vechvu"`):
  - Routes directly to `handleOwnerFlow()` without resetting or dropping their booked visit.
- When a lead with a booked visit inquires about another property category (`"Office"`, `"3BHK"`):
  - Routes to `handleQualificationCascade()` to capture the additional inquiry.

### 3. Smart Catch-All Forwarding & HTML Tag Fix
- Replaced dead-end catch-all: if user's input contains an extracted `property_type`, `location`, or `budget`, forward directly to `handleQualificationCascade()` instead of repeating the generic question.
- Fixed `nameStr` definitions in `dispatchStateAction` and `handleQualificationCascade` to remove embedded `<b>...</b>` tags, eliminating double bolding (`<b><b>Name ji</b></b>`).
