# Plan 37.1: First-Turn Intake Triage, Modern Apple HIG / WhatsApp-Ergonomic Greeting & Auto-Bypass Rule

## Context & Objectives
In real estate agencies, customer inbound inquiries fall into two main categories:
1. **Acquisition (Seeker)**: Property leni hai (*Buy / Rent / Commercial Lease*)
2. **Disposition (Owner / Provider)**: Apni property list/deni hai (*Sell / Rent Out / Commercial Lease Out*)

Currently, when a user sends an ambiguous greeting or inquiry (e.g. *"Can I get more info on this"*), the engine assumes `BUY` and immediately prompts for property type (*"Aap kis type ki property dekh rahe hain — 2/3 BHK Flat, Villa ya Commercial Shop/Office?"*).
We will implement a clean, respectful, 2-stage intake triage:
- **Level 1**: Property Leni Hai (*Buy / Rent / Lease*) vs Apni Property List Karni Hai (*Sell / Rent Out*).
- **Level 2**: Transaction type clarification (Buy vs Rent vs Lease for Seekers; Sell vs Rent Out vs Lease Out for Owners).
- **Auto-Bypass**: If the user's initial message already contains concrete intent (e.g. *"3bhk flat leni che"*, *"office rent par deni hai"*), auto-bypass the triage menu and route directly.
