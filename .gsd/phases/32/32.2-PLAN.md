# Plan 32.2: Stale Location Confirmation & Smart Contextual Resume Engine

## Objective
1. Prevent silent stale location leakage (e.g. "Vasna-Bhayli Road" auto-injection) by introducing an interactive `LOCATION_CONFIRMATION` prompt when historical location data exists in `lead.location` or `seeker_draft.location`.
2. Allow user to either keep previous location (Option 1) or specify/type a new location (Option 2), immediately updating and persisting the new choice.
3. Build a Smart Contextual Resume Engine: When a returning user sends a greeting ("Hi", "Hello") after leaving an incomplete inquiry, display a structured Recap Card summarizing what was collected and offering a dual-fork choice (1 = Continue previous inquiry, 2 = Start fresh search).
4. Allow direct answer bypass: If a returning user directly answers the pending question (e.g. "Ready to move") without greeting, seamlessly auto-resume without showing redundant recap friction.
5. Verify complete end-to-end multi-turn journeys with automated tests and TypeScript compilation.

## Tasks

### Task 1: Stale Location Interactive Confirmation & Switching Flow
<files>
supabase/functions/realtor-lead-engine/index.ts
</files>
<action>
1. In `handleQualificationCascade` (where `location` is resolved):
   - Check if current turn message provided an explicit location (`justLoc`). If yes, use and update it.
   - If current message did NOT provide a location, BUT `lead.location` or `lead.metadata.seeker_draft.location` has a cached/stale location (`staleLoc`), and the user has not yet confirmed it:
     - Do NOT auto-set `location = staleLoc`!
     - Instead, set `missingStage = "LOCATION_CONFIRMATION"`.
     - In prompt generation for `LOCATION_CONFIRMATION`:
       - Hinglish: `Humare paas aapki pichli location <b>${staleLoc}</b> saved hai. 📍\n\nKya aap <b>${staleLoc}</b> me hi aage badhna chahte hain, ya koi nayi location batana chahte hain?\n\n1️⃣ Pichli location (${staleLoc})\n2️⃣ Nayi location batayein`
       - Gujlish: `Amari pase tamari paheli ni location <b>${staleLoc}</b> saved chhe. 📍\n\nShu tame <b>${staleLoc}</b> ma j aagal vadharva mango chho ke navi location badalvi chhe?\n\n1️⃣ Paheli ni location (${staleLoc})\n2️⃣ Navi location janavo`
       - English: `We have your previous location saved as <b>${staleLoc}</b>. 📍\n\nWould you like to proceed with <b>${staleLoc}</b>, or specify a new location?\n\n1️⃣ Keep previous location (${staleLoc})\n2️⃣ Change to new location`
2. In user response handling:
   - If user replies `1` / `pichli` / `purani` / `ha` / `yes`:
     - Lock and confirm `location = staleLoc`, mark `location_confirmed = true` in metadata, and advance to next missing stage.
   - If user replies `2` / `nayi` / `change` OR provides a new locality name:
     - If locality name is detected in the input, set `location = newLoc`, update `lead.location` and `seeker_draft.location`, and clear old stale cache.
     - If user simply sent "2" or "change", prompt for the new location name: `👉 Kripya apni nayi preferred location / area ka naam batayein. 📍`.
</action>

2. Replying "1" retains "Vasna-Bhayli Road".

### Task 2: Smart Contextual Resume Engine & Dual-Fork Re-engagement
<files>
supabase/functions/realtor-lead-engine/index.ts
</files>
<action>
1. In `dispatchStateAction` (at entry/greeting detection for returning leads):
   - Detect if incoming message is a pure greeting (`isGreeting`: "hi", "hello", "hey", "namaste", "kem cho") and lead has an incomplete `seeker_draft` (has at least 1-2 fields filled, e.g. property type or budget or location, but `missingStage` exists):
     - Format a crisp, professional Recap Card:
       - Header: `Namaste ${senderName}! 🙏 Welcome back.`
       - Summary of captured items:
         - Property Type (e.g. `• Property: 3 BHK Flat (Buy)`)
         - Location (e.g. `• Location: Vasna-Bhayli Road 📍`)
         - Budget (e.g. `• Budget: ₹60 - 85 Lakhs 💰`)
         - Pending item note: `(Pending: ${pendingFieldName})`
       - Dual-Fork Action Menu:
         `Aap kaise aage badhna chahenge?\n1️⃣ Pichli inquiry yahin se continue karein\n2️⃣ Nayi inquiry shuru karein (New Search)`
     - Set state to `RESUME_CONFIRMATION_PENDING` with previous draft preserved in metadata.
2. In `RESUME_CONFIRMATION_PENDING` handler:
   - If user selects Option 1 (`1`, `continue`, `yes`, `aage badho`):
     - Resume immediately at `missingStage` of previous draft.
   - If user selects Option 2 (`2`, `new`, `nayi`):
     - Archive existing `seeker_draft` into `seeker_profile.searches`, clear current draft, and present clean fresh triage prompt.
3. Direct Answer Bypass Guard:
   - If incoming message contains an entity answering the pending question (e.g. user sends "Ready to move" or "Under construction" when `TIMELINE` was pending):
     - Do NOT display Recap Card! Directly accept the entity, update the draft, and advance the cascade seamlessly.
</action>
<verify>
Run scratch test verifying:
1. Returning user with incomplete draft sending "Hi" receives the Recap Card with Option 1 & Option 2.
2. User selecting Option 1 resumes from the pending question.
3. User selecting Option 2 archives old draft and starts fresh.
4. Returning user sending "Ready to move" directly auto-resumes without recap friction.
</verify>
<done>
Contextual session resume eliminates bot amnesia, provides a clean dual-fork menu, and respects direct entity inputs.
</done>
