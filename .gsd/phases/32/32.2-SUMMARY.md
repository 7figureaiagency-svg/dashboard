## Overview
Implemented Point 5 (Stale Location Confirmation & Switching) and the Smart Contextual Resume Engine:
1. **Interactive Stale Location Confirmation (Point 5):**
   - Added `LOCATION_CONFIRMATION` missing stage in `handleQualificationCascade`.
   - When a lead has a cached location (like "Vasna-Bhayli Road") from previous interactions, the bot never silently auto-fills it.
   - The bot proactively prompts:
     `Humare paas aapki pichli location Vasna-Bhayli Road saved hai. 📍\nKya aap Vasna-Bhayli Road me hi aage badhna chahte hain, ya koi nayi location batana chahte hain?\n\n1️⃣ Pichli location (Vasna-Bhayli Road)\n2️⃣ Nayi location batayein`
   - Option 1 locks the saved location; Option 2 allows specifying and persisting a new location.
2. **Smart Contextual Resume Engine:**
   - Created `buildContextualRecapCard()` and `hasIncompleteSeekerDraft()`.
   - When a returning user sends a greeting ("Hi", "Hello", "Kem cho") with an incomplete inquiry draft, the bot displays a structured Recap Card showing noted property details, pending fields, and a dual-fork choice (1 = Continue previous inquiry, 2 = Start fresh search).
   - Direct answer bypass: If user returns and directly sends an entity answer (e.g. "Ready to move"), the bot auto-resumes without recap friction.
