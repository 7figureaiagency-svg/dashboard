# Plan 10.1: Multi-Tenant Query Scoping in realtor-lead-engine Edge Function

## Objective
Enforce strict multi-tenant scoping (`.eq("client_id", activeTenantId)`) on every database query in `supabase/functions/realtor-lead-engine/index.ts` (specifically `property_submissions`, `inventory`, and `site_visits`). Because the Edge Function uses `SUPABASE_SERVICE_ROLE_KEY`, unscoped queries bypassed PostgreSQL RLS, causing Nextgen Realty's seller submissions (e.g. `Spring field`) to be returned when a lead interacted with Griham Realty's bot, which falsely escalated pure buyers to `DUAL_ROLE`.

## Invariants
1. **100% Non-n8n Architecture:** All logic stays in Supabase Edge Functions + PostgreSQL + React frontend.
2. **Strict Multi-Tenant Isolation:** No database query in the Edge Function may omit `.eq("client_id", activeTenantId)`.
3. **0 Extra JS Packages:** Pure TypeScript.
