# Plan 11.1: Activity Engine & Unified Actor Normalizer (Backend & Data Layer)

<objective>
Refactor the CRM lead activity and event data pipeline. Persist human executive actions to `public.lead_events` (since `lead_activity` table does not exist in PostgreSQL), and normalize `lead_events` into crisp, categorized activity items (`SALES_REP` vs `AI_BOT`). Strip raw multi-line HTML bot speeches and chat transcript dumps in favor of clean 1-line action summaries so that the history stream does not explode in height.

Purpose: Provide a reliable, lightweight, actor-segregated data source for the Lead Profile History tab.
Output: Enhanced `src/lib/crm.ts` and `src/lib/crm-data.ts` with actor categorization and concise event summarization.
</objective>

<context>
Load for context:
- `src/lib/crm.ts` (`Activity`, `actionLabel`, `ACTION_LABELS`, `buildActivityRows`)
- `src/lib/crm-data.ts` (`useActivity`, `useUpdateLead`)
- `src/integrations/supabase/types.ts` (`lead_events` Row/Insert schema)
</context>

<tasks>

<task type="auto">
  <name>Actor Classification & Concise Event Summarizer Taxonomy</name>
  <files>src/lib/crm.ts</files>
  <action>
    1. Define `ActorType = "SALES_REP" | "AI_BOT" | "SYSTEM"`.
    2. Augment `Activity` type to include:
       - `actor_type: ActorType`
       - `actor_label: string` (e.g. "Amit (Sales)", "AI Assistant", "System Engine")
       - `short_summary: string` (a concise 1-line description of what occurred, e.g. "Called lead - interested in Alkapuri 3BHK", "Confirmed VIP Site Visit for 24 Oct", "Shared 3 property brochures", "Updated status to QUALIFIED")
       - `details?: string | null` (optional expanded notes or changes)
    3. Create `summarizeLeadEvent(eventType: string, payload: any, executiveName?: string | null)`:
       - Detects if event is from human sales executive (`source === "EXECUTIVE_ACTION"` or `executiveName` present or action in `["CALL_LOGGED", "CALL_NOT_ANSWERED", "NOTE_ADDED", "TAKEOVER", "ASSIGN_EXECUTIVE", "PHONE_ADDED", "STATUS_CHANGE"]`).
       - If AI bot event (`MESSAGE_PROCESSED`, `OPTIONS_SENT`, `SITE_VISIT_BOOKED`, `PRE_VISIT_REMINDER_SENT`, `FEEDBACK_SURVEY_SENT`):
         - Extracts intention from payload without dumping the 15-line `replySent` HTML blob.
         - For example: if `payload.replySent` mentions "VIP Site Visit" or `event_type === "SITE_VISIT_BOOKED"`, summary = "AI booked VIP Site Visit"; if options were sent, summary = `AI shared property options (${payload.matched_properties?.length || 3} units)`; if `payload.state === "QUALIFYING"`, summary = `AI qualifying buyer requirement (${payload.userText || ""})`; if general greeting, summary = "AI greeted lead and resumed search".
       - Strips HTML tags (`<b>`, `</b>`, `\n`) and emojis cleanly for titles.
    4. Create `groupActivityByDate(activities: Activity[])` grouping items into "Today", "Yesterday", "This Week", and "Earlier".
    AVOID: Returning full multi-line chat message text in `note` because it bloats cards and duplicates the WhatsApp Chat tab.
  </action>
  <verify>Run `npm.cmd run build` to confirm zero TypeScript compilation errors.</verify>
  <done>src/lib/crm.ts exports actor classification, concise summarization, and date grouping functions.</done>
</task>

<task type="auto">
  <name>Executive Action Persistence in lead_events & Enriched useActivity Hook</name>
  <files>src/lib/crm-data.ts</files>
  <action>
    1. In `useUpdateLead()`:
       - When `lead && action` is present, insert into `public.lead_events`:
         ```ts
         await supabase.from("lead_events").insert({
           client_id: lead.client_id || clientId,
           lead_id: lead.lead_id,
           event_type: action,
           payload: {
             source: "EXECUTIVE_ACTION",
             executive_name: lead.assigned_executive_name || "Sales Executive",
             action,
             field: r.field,
             old_value: r.old_value,
             new_value: r.new_value,
             note: note || values.executive_notes || null,
           }
         });
         ```
       - This guarantees human executive actions are persisted into the PostgreSQL audit log and immediately appear in the History timeline.
    2. In `useActivity(passedClientId)`:
       - Fetch `lead_events` for the current tenant.
       - Map each event using `summarizeLeadEvent` from `src/lib/crm.ts`.
       - Populate `actor_type`, `actor_label`, `short_summary`, `details`, and clean `created_at`.
       - Invalidate `["lead_activity", clientId]` and `["lead_events", leadId]` upon mutations.
    AVOID: Relying on the non-existent `public.lead_activity` table. Use `public.lead_events` as the single unified source of truth.
  </action>
  <verify>Run `npm.cmd run build` to ensure zero compilation regressions.</verify>
  <done>useUpdateLead persists executive actions to lead_events, and useActivity returns normalized, actor-typed activities.</done>
