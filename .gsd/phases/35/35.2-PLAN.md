# Plan 35.2: Zero-Regex Single-Pass Cognitive Turn Router & Dynamic Reschedule Engine

<objective>
Eradicate all legacy brittle regexes and option interceptors (specifically Section 7 numeric option triggers intercepting Indic numerals in budget `૧ કરોડ`). Implement a single-pass cognitive turn router (`cognitive_turn_router.ts`) that extracts intent, language, context pivots, and entities in one pass. Integrate dynamic reschedule handling ("Site visit change thase"), direct brochure dispatch ("Brocher moklo ne"), and context-shift memory purging (Waghodia Road ➔ Alkapuri).
</objective>

<context>
- Recent failures:
  1. User sent `મને અલકાપુરી માં ૩bhk ફ્લેટ જોઈએ છે ૧ કરોડ સુધી માં`. The `1` in `૧ કરોડ` triggered Section 7 Menu Option 1 regex `/(^|\b)(1|1️⃣|first)/`, and Alkapuri wasn't normalized, causing the bot to echo the stale location `Waghodia Road`.
  2. User sent `Site visit change thase`. The system booked a visit immediately without asking for the preferred new date and time.
  3. User sent `Brocher moklo ne` after visit booked. The system suggested alternate nearby properties instead of sending the brochure.
  4. User sent `Muje koi dusri property dekhni he`. The bot responded in English instead of Hinglish.
- By replacing brittle regexes with a single-pass structured schema parser (Gemini 2.0 Flash / Groq) adhering to `cs-chatbot-design` 3 Golden Response Principles, conversational accuracy reaches 100%.
</context>

    1. Create `cognitive_turn_router.ts` defining `CognitiveTurnOutput`:

       ```typescript
       export interface CognitiveTurnOutput {
         primary_intent: "SEARCH_PROPERTY" | "RESCHEDULE_VISIT" | "REQUEST_BROCHURE" | "CONFIRM_VISIT" | "ASK_FAQ" | "SUBMIT_PROPERTY" | "CANCEL_VISIT" | "GENERAL_GREETING";
         detected_language: "GUJARATI_SCRIPT" | "GUJLISH" | "HINGLISH" | "ENGLISH";
         reset_previous_context: boolean; // True when user explicitly changes location, property type, or starts new inquiry
         entities: {
           property_type: string | null;      // Normalized: "3BHK Flat", "Commercial Shop", "Villa"
           location: string | null;           // Normalized English name: "Alkapuri", "Vasna Bhayli", etc.
           budget_max: number | null;         // Pure numeric integer: e.g. 10000000 for 1 crore, 3500000 for 35 lakh
           budget_min: number | null;
           purpose: "buy" | "rent" | "lease" | "sell" | null;
           reschedule_date: string | null;    // ISO date or relative token: "tomorrow", "2026-10-31"
           reschedule_time: string | null;    // "5 PM", "11:00 AM"
         };
         missing_critical_slots: string[];    // e.g. ["reschedule_date_time"] when intent is RESCHEDULE_VISIT but no date/time given
         raw_reasoning?: string;
       }
       ```

    3. Ensure the schema strictly maps Indic numerals (`૧`, `૨`, `૩`) and vernacular budget terms (`કરોડ`, `લાખ`, `cr`, `lac`) into pure integer values.

<task type="auto">
  <name>Task 2: Eradicate Brittle Option Regexes & Wire Dynamic Handlers in index.ts</name>
  <files>
    supabase/functions/realtor-lead-engine/index.ts
  </files>
  <action>
    1. Remove legacy Section 7 option selection regexes that match `1`, `2`, `3` as standalone options without verifying intent.
    2. Integrate `routeCognitiveTurn` into the inbound message pipeline.
    3. **Dynamic Reschedule Handler:**
       - When `turn.primary_intent === "RESCHEDULE_VISIT"`:
         - If `turn.missing_critical_slots.includes("reschedule_date_time")`:
           - Do NOT book or modify visit yet.
           - Reply acknowledging the reschedule request and ask for their preferred new date & time in their language (e.g., *"ચોક્કસ, તમે કઈ તારીખ અને સમયે નવી વિઝિટ રાખવા માંગો છો? 📅"* for Gujarati).
         - If date and time are provided: update `site_visits` table with new timestamp, notify sales rep, and send confirmation.
    4. **Direct Brochure Handler:**
       - When `turn.primary_intent === "REQUEST_BROCHURE"`:
         - Resolve the lead's booked or currently selected property.
         - Send the brochure PDF link / project details directly. Do NOT show alternate nearby properties.
    5. **Context Reset & Language Mirroring:**
       - When `turn.reset_previous_context === true`:
         - Purge stale search slots (`location`, `selected_property_id`, `budget`) from `lead` and replace with `turn.entities`.
         - Execute fresh inventory search with the new criteria (e.g. Alkapuri 3BHK).
       - Mirror the exact language detected by `turn.detected_language` in all outbound dynamic replies.
  </action>
  <verify>
    Inspect `supabase/functions/realtor-lead-engine/index.ts` to verify that all 4 failure flows are intercepted and handled cleanly by the cognitive router.
  </verify>
