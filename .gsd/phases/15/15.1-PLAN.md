# Plan 15.1: Precision Inventory Demand Matchmaker & Explicit Property Locking

<objective>
Fix the flawed Reverse Demand Matchmaker logic in the Live Inventory tab.
Currently, a lead who booked a site visit for a specific property (e.g. Manthan for "Griham Heights Luxury Residences") is incorrectly displayed as a matching buyer across multiple unrelated properties (a Commercial Office and a Residential Plot) because:
1. `selected_property_id` is ignored, allowing dedicated buyers to leak into unrelated properties.
2. A loose threshold (`score >= 2`) allows a high budget alone to match every cheaper property in inventory regardless of category or location.
3. Category isolation between Residential, Commercial, and Plot is missing.
4. Card view has an undefined `setDemandModalProp` function call.

Refactor the matching algorithm to enforce explicit property locking, strict category isolation, dual-factor demand qualification, and clear visual indicators in the matching buyers modal.
</objective>

</context>

<task type="auto">
  <name>Refactor matchingBuyersMap with Explicit Property Locking & Category Isolation</name>
  <files>src/components/crm/inventory-tab.tsx</files>
  <action>
    Refactor `matchingBuyersMap` inside `src/components/crm/inventory-tab.tsx`:
    1. **Explicit Property Locking**:
       - Check if lead `l.selected_property_id` is set (e.g. `"PROP-GRI-001"`).
       - If `l.selected_property_id === p.property_id`, IMMEDIATELY match as a dedicated property buyer (return true).
       - If `l.selected_property_id` is set and does NOT match `p.property_id`, IMMEDIATELY reject (return false). This guarantees that a lead who chose or booked a visit for Griham Heights will NEVER appear under Griham Business Central or Griham Green Valley.
    2. **Strict Category Isolation (for generic/unassigned leads)**:
       - Extract normalized category from property `p.property_category` (`FLAT`, `VILLA`, `COMMERCIAL`, `PLOT`, etc.).
       - Extract lead `property_type` or requirement.
       - If property is `COMMERCIAL`, lead MUST explicitly seek commercial (office, shop, retail, showroom). Residential leads cannot match commercial.
       - If property is `PLOT`, lead MUST explicitly seek plot/land.
       - If property is `FLAT` or `VILLA`, commercial or plot seekers cannot match.
    3. **Multi-Factor Score Qualification (No Budget-Only Matches)**:
       - Require at least TWO congruent factors (e.g. Category/Config match + Realistic Budget within 0.7x to 1.3x property price, or Location match + Category match).
       - Budget alone must NEVER qualify a lead.
    4. **Fix Card View Undefined Handler**:
       - Replace `onClick={() => setDemandModalProp(p)}` on line 971 with `onClick={() => setMatchingDialogProperty({ property: p, buyers: matchingBuyers })}`.
    AVOID: Loosely matching on budget alone or allowing leads with an explicit selected_property_id to bleed into other properties.
  </action>
