# Plan 36.1: PropTech Matching Precision (Duplex / Villa / Penthouse) & Short Budget Parsing

<objective>
Eliminate the property matching asymmetry that caused approved duplex inventory to be rejected for leads like "Manthan", and fix the budget underflow bug where short numbers under 15 (e.g., "budget 10" or "under 12") fail to parse.
</objective>

<context>
- In `supabase/functions/realtor-lead-engine/index.ts` lines 5190-5197 (`matchesPropertyType`), `isLeadVilla` matches `"duplex"`, but `isPropVilla` regex only checked `(villa|bungalow|row_house|farm_house)` and checked `cat === "villa"`.
- If an inventory unit has `configuration: "3BHK Duplex"` or `project_name: "Duplex"`, but its `category` is `"RESIDENTIAL"` or `"FLAT"`, `isPropVilla` evaluates to `false` and `cat !== "villa"` is true, causing the function to execute `return false` and reject the matching property.
- In `parseBudgetFromText` lines 1628-1632, `shortNumMatch` enforces `val >= 15 && val <= 500`. If a user enters "budget 10" or "under 12" (meaning 10 or 12 Lakh for buyers, or 10k or 12k for rentals), it returns 0 because `val < 15`.
</context>

         - Match if `combined.includes("duplex")` or `propSub.includes("duplex")` or `cat === "duplex"`.

       - For general villa/bungalow queries:
         - Match if property is villa, bungalow, row house, farmhouse, or duplex.
         - Do not falsely reject properties where `category` is "RESIDENTIAL" or "FLAT" if `combined` explicitly contains `duplex` or `villa`.
       - Ensure bidirectional consistency for penthouse as well.
