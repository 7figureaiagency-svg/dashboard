# Plan 27.2: Conversational Side-Question Interception, Seamless State Resumption & Multi-Entity Draft Archival

<objective>
Implement conversational detour interception with instant single-turn state resumption (`metadata.suspended_state`) for in-flight FAQs during owner intake and buyer qualification. Deliver multi-entity draft archival (`metadata.completed_submissions[]` and fresh `owner_draft`) and secondary buyer search preservation (`metadata.seeker_profile.searches[]`) with zero data wipes or state deadlocks.

Purpose: Allow leads to ask natural side questions (e.g. office address, RERA, brokerage) without losing their intake progress, and empower multi-property owners and multi-search buyers to manage multiple transactions simultaneously.
Output: Upgraded `handleFaqResponse`, detour resumption handlers, and multi-entity lifecycle management in `supabase/functions/realtor-lead-engine/index.ts`.
</objective>

<task type="auto">
  <name>Conversational Detour Interceptor & Instant State Resumption</name>
  <files>supabase/functions/realtor-lead-engine/index.ts</files>
  <action>
    Implement detour interception and resumption in `supabase/functions/realtor-lead-engine/index.ts`:
    1. **Detour State Detection in `dispatchStateAction`:**
       - Detect when `intent === "ASK_FAQ"` occurs while the user is inside an active intake workflow:
         - Owner Intake: `currentState.startsWith("OWNER_") && currentState !== "OWNER_DETAILS_GATHERED"`
         - Buyer Qualification: `currentState === "QUALIFYING"`
         - Role Triage: `currentState === "ROLE_SELECTION_PENDING"`
         - Visit Slot Booking: `currentState === "OPTIONS_SENT" || currentState === "VISIT_REQUESTED" || currentState === "SITE_VISIT_PROPOSED"`
       - Record active context into `metadata.suspended_state`:
         ```ts
         lead.metadata = {
           ...(lead.metadata || {}),
           suspended_state: {
             previous_state: currentState,
             suspended_at: new Date().toISOString(),
             intake_type: currentState.startsWith("OWNER_") ? "OWNER" : "SEEKER",
             pending_field: deriveBotQuestionType(currentState, ""),
           },
         };
         ```
    2. **Upgrade `handleFaqResponse` with Dual-Payload Single-Turn Resolution:**
       - If `lead.metadata?.suspended_state` is present or user is in active intake:
         - Generate the accurate FAQ answer for the requested topic (`OFFICE_ADDRESS`, `OFFICE_TIMINGS`, `AGENCY_INFO`, `RERA`, `BROKERAGE`, `LOAN`, `CUSTOM_FAQ`).
         - **Suppress** the default generic site-visit CTA (`bridgeCta`) that asks "VIP Site Visit schedule karie?".
         - **Append** a stage-aware resumption prompt in the active language (`GUJLISH`, `HINGLISH`, `ENGLISH`):
           - In `OWNER_CONFIG_PENDING`: "Ab aage badhte hain — aapki property kis type ki hai (Flat, Villa, Shop, Office)? 🏢"
           - In `OWNER_SOCIETY_PENDING`: "Ab aage badhte hain — aapki property kis Society, Project ya Road par sthit hai? 📍"
           - In `OWNER_LOCATION_PENDING`: "Ab aage badhte hain — aapki property kis Area ya Locality me aati hai? 📍"
           - In `OWNER_AREA_PENDING` / `OWNER_SIZE_PENDING`: "Ab aage badhte hain — property ka Carpet ya Built-up Area kitna hai? 📏"
           - In `OWNER_PRICE_PENDING`: "Ab aage badhte hain — aapka expected Selling Price ya Monthly Rent kitna hai? 💰"
           - In `OWNER_POSSESSION_PENDING`: "Ab aage badhte hain — Possession status kya hai (1 Ready to Move, 2 Under Construction)? 🔑"
           - In `OWNER_FURNISHING_PENDING`: "Ab aage badhte hain — Furnishing status kya hai (1 Unfurnished, 2 Semi-Furnished, 3 Fully Furnished)? 🛋️"
           - In `QUALIFYING`: Dynamically prompt for the active missing turn (Turn 1 Property Type/Tx, Turn 2 Locality/Budget, or Turn 3 Timeline/Purpose).
           - In `ROLE_SELECTION_PENDING`: Re-prompt the 3-choice role triage menu.
           - In `OPTIONS_SENT` / `VISIT_REQUESTED`: "Ab aage badhte hain — aap kis date ya time par VIP Site Visit plan karna chahenge? 🚗"
         - Return `nextState: suspended_state.previous_state` (maintaining the active intake stage).
         - Return `leadUpdates` preserving existing `owner_draft` and `seeker_draft`.
    3. **Post-Detour Resumption Cleanup:**
       - On the subsequent turn, when user answers the resumed question, clear `metadata.suspended_state = null` while preserving all draft attributes.

    AVOID: Resetting the conversation to FRESH, asking about site visits during an owner listing flow, or losing accumulated draft attributes.
    USE: A dual-payload response in 1 turn (Answer + Resumption Prompt) that retains the exact intake state and accumulated draft.
  </action>

    1. **Multi-Entity Owner Draft Archival (`metadata.completed_submissions[]`):**
       - In `handleOwnerFlow` when an intake completes and transitions to `OWNER_DETAILS_GATHERED`:
         - Retrieve `metadata.completed_submissions` (or initialize empty array if absent).
         - Format the completed property snapshot:
           ```ts
           const completedSnapshot = {
             submission_id: existingMeta.submission_id || null,
             completed_at: new Date().toISOString(),
             transaction_type: draft.transaction_type || "SELL",
             property_type: draft.property_type || null,
             project_or_society: draft.project_or_society || null,
             location: draft.location || null,
             price_or_rent: draft.expected_price || draft.expected_rent || null,
             carpet_sqft: draft.carpet_area_sqft || null,
             super_built_up_sqft: draft.super_built_up_sqft || null,
             possession_status: draft.possession_status || null,
             furnishing_status: draft.furnishing_status || null,
             parking_status: draft.parking_status || null,
             contact_phone: draft.contact_phone || null,
             status: "PENDING_VERIFICATION",
           };
           ```
         - Append `completedSnapshot` to `metadata.completed_submissions`.
         - Synchronize with legacy `metadata.archived_submissions` for backward compatibility.
       - **Initiating Subsequent Listings (2nd / 3rd Property):**
         - When user in `OWNER_DETAILS_GATHERED` requests to list another property (replying "2" or saying "ek aur flat bechna hai"):
           - Keep `metadata.completed_submissions` array completely intact.
           - Reset `metadata.owner_draft = { attributes: {} }`.
           - Set `metadata.submission_id = null`.
           - Set `metadata.declined_second_listing = false`.
           - Parse initial configuration from the user's message (e.g. "office rent par dena hai" -> `property_type = "Office"`, `transaction_type = "RENT_OUT"`).
           - Advance cleanly to `OWNER_CONFIG_PENDING` or `OWNER_SOCIETY_PENDING`.
    2. **Multi-Search Buyer Lifecycle Preservation (`metadata.seeker_profile.searches[]`):**
       - In `handleQualificationCascade`:
         - When a qualified lead with an existing site visit or search initiates a secondary search (`intent === "CHANGE_REQUIREMENT"` or "naya option dekhna hai"):
           - Preserve `site_visit_booked`, `visit_booked_at`, and `preferred_slot`. Do NOT cancel or nullify the scheduled visit.
           - Archive the existing search criteria into `lead.metadata.seeker_profile.searches[]`:
             ```ts
             const existingSearches = Array.isArray(lead.metadata?.seeker_profile?.searches)
               ? [...lead.metadata.seeker_profile.searches]
               : [];
             existingSearches.push({
               searched_at: new Date().toISOString(),
               property_type: lead.property_type || null,
               requirement: lead.requirement || null,
               budget: lead.budget || null,
               location: lead.location || null,
               timeline: lead.timeline || null,
               purpose: lead.purpose || null,
             });
             ```
           - Initialize the new search criteria in `leadUpdates` without touching the scheduled visit.
           - Retain active lead score and hot lead temperature.

    AVOID: Overwriting the previous property submission in `owner_draft` when a second property is started, or canceling existing site visits when a buyer searches again.
    USE: An explicit archival array (`completed_submissions` for owners and `seeker_profile.searches` for buyers) that guarantees dual-entity data isolation.
